# 알림톡 문구 아홉 개

- **정한 날** 2026-09-05 · **정한 사람** 소유자(여동현) 검토 후 확정
- **상태** 대표 확인 대기 → 카카오톡 설정 화면에서 등록 → 심사
- **근거** `docs/decisions/003-scenario-redesign-2026-09-05.md` §3 · 뿌리오 개발 문서(2026-09-05 실측)

## 🔴 먼저 읽을 것

**심사를 통과한 문구는 변수 자리 말고 못 고친다.** 고치려면 다시 며칠이 걸린다.
그래서 아홉 개를 **한 번에** 등록한다 — 나중에 하나 빠진 걸 발견하면 그때 또 기다린다.

**알림톡은 안내만 보낼 수 있다.** 「다음 회차도 신청하세요」 같은 권유는 광고라 반려된다.
⑦의 「다음 모임을 더 낫게 만드는 데 쓰겠습니다」를 뺀 것이 그 이유다.

### 계좌번호를 문구에 넣지 않는다

링크로만 보낸다. 계좌를 문구에 박으면 **계좌가 바뀔 때 아홉 개를 다시 심사받아야 한다.**
링크로 보내면 계좌가 바뀌어도 심사 문구는 그대로다.
이 규칙 때문에 `#{계좌}`·`#{은행}`·`#{예금주}` 변수가 목록에서 빠졌다.

### 🔴 본문에 링크를 글자로도 넣는다

버튼만 두면 안 된다. **알림톡이 실패해 문자로 대체 발송되면 버튼이 통째로 사라진다**
(뿌리오 문서 실측). 그러면 「아래에서 확인하세요」라고 써놓고 갈 곳이 없는 문자가 나간다.

그래서 모든 문구에 `▶ #{링크}` 줄을 넣는다. 버튼은 그 위에 얹는 편의 장치일 뿐이다.
덕분에 **대체 문자 문구를 따로 쓰지 않아도 된다** — 본문을 그대로 쓴다.

### 🔴 버튼 주소에는 변수를 못 쓴다

카카오 버튼(`WL`)의 `url_mobile`은 **완성된 주소**여야 한다. `#{}`가 안 통한다.
보낼 때 우리가 **그 사람의 주소를 통째로 만들어** 넣는다. 도메인은 고정, 뒤의 토큰만 다르다.

### 주소를 짧게 유지한다

`#{링크}`가 문자에 글자 그대로 찍힌다. 토큰이 길면 문자 한 통이 길어지고 보기에도 지저분하다.
`hangyeol.kr/me/<짧은토큰>` 형태를 유지한다.

## 변수 아홉 개

`#{이름}` `#{입금액}` `#{입금기한}` `#{링크}` `#{행사일}` `#{시간}` `#{장소}` `#{환불액}` `#{처리일}`

🔴 **여기 없는 변수를 문구에 쓰지 않는다.** 채우지 못한 변수가 남으면 발송이 거부되고,
막지 않으면 `#{계좌}`가 그대로 박힌 문구가 손님에게 나간다.

## ① 입금 안내

- **언제** 신청 폼이 저장되는 순간 — 🔴 **아홉 개 중 유일하게 자동**
- **버튼** `신청 이어서 하기`

```
[한결] 신청이 접수되었습니다

#{이름}님, 한결 1차 모임 신청을 받았습니다.

아래 링크에서 참가 정보를 입력하고 입금해 주세요.
입금이 확인되면 자리가 확정됩니다.

· 참가비 #{입금액}
· 입금 기한 #{입금기한}

▶ #{링크}
```

## ② 대기 명단 등록

- **언제** 자리가 이미 찼을 때 신청한 사람에게
- **버튼** `내 신청 확인하기`

```
[한결] 대기 명단에 등록되었습니다

#{이름}님, 신청해 주셔서 감사합니다.

현재 #{행사일} 모임의 자리가 모두 찼습니다.
대기 명단에 등록해 두었고, 자리가 생기면 순서대로 연락드립니다.

신청 내용은 아래에서 확인하실 수 있습니다.

▶ #{링크}
```

> 대기자에게 **자리가 났다고 알릴 때는 ①을 다시 보낸다.** 필요한 정보가 똑같아 따로 만들지 않는다.

## ③ 입금 기한 임박

- **언제** 기한 12시간 전쯤
- **버튼** `계좌 확인하기`

```
[한결] 입금 기한이 얼마 남지 않았습니다

#{이름}님, #{입금기한}까지 입금이 확인되지 않으면
자리를 확정해 드리기 어렵습니다.

참가비 #{입금액}, 계좌는 아래 링크에서 확인하실 수 있습니다.

▶ #{링크}

이미 입금하셨다면 확인까지 시간이 조금 걸릴 수 있습니다.
```

## ④ 자리 확정 + 사전 질문 요청

- **언제** 운영자가 입금을 확인한 뒤
- **버튼** `사전 질문 답하기`

```
[한결] 자리가 확정되었습니다

#{이름}님, 입금이 확인되어 #{행사일} 모임 자리가 확정되었습니다.

· #{행사일} #{시간}
· #{장소}

이제 사전 질문 열 개에 답해 주세요.
답변은 당일 대화 상대를 정하는 데 쓰입니다.
행사 사흘 전까지 부탁드립니다.

▶ #{링크}
```

## ⑤ 사전 질문 미제출 안내

- **언제** 행사 사흘 전쯤, 아직 안 낸 사람에게
- **버튼** `사전 질문 답하기`

```
[한결] 사전 질문이 아직 도착하지 않았습니다

#{이름}님, #{행사일} 모임이 사흘 남았습니다.

사전 질문 답변이 아직 없습니다.
답변이 없으면 당일 대화 상대를 정하기 어렵습니다.
오늘 안에 부탁드립니다.

▶ #{링크}
```

## ⑥ 행사 전날 안내

- **언제** 행사 전날
- **버튼** `안내 다시 보기`

```
[한결] 내일 뵙겠습니다

#{이름}님, #{행사일} 모임이 내일입니다.

· 시간 #{시간}
· 장소 #{장소}

늦지 않게 도착해 주세요. 이름표는 현장에서 드립니다.
사정이 생기셨다면 오늘 중으로 알려 주시면 감사하겠습니다.

▶ #{링크}
```

## ⑦ 후기 안내

- **언제** 행사 다음 날
- **버튼** `후기 남기기`

```
[한결] 어제 함께해 주셔서 감사합니다

#{이름}님, 어제 모임에 함께해 주셔서 감사합니다.

짧은 후기를 남겨 주시면 감사하겠습니다. 3분이면 충분합니다.

▶ #{링크}
```

## ⑧ 환불 완료

- **언제** 환불을 보낸 뒤
- **버튼** `내역 확인하기`

```
[한결] 환불이 완료되었습니다

#{이름}님, 환불 처리가 끝났습니다.

· 환불 금액 #{환불액}
· 처리일 #{처리일}

입금하신 계좌로 보내 드렸습니다.
은행에 따라 반영까지 하루 정도 걸릴 수 있습니다.
내역은 아래에서 확인하실 수 있습니다.

▶ #{링크}
```

## ⑨ 리포트 안내

- **언제** 리포트가 나온 뒤
- **버튼** `리포트 보기`

```
[한결] 모임 리포트가 나왔습니다

#{이름}님, #{행사일} 모임의 리포트를 정리했습니다.
당일 오간 이야기와 전체 흐름을 담았습니다.

▶ #{링크}
```

## 만들지 않는 것

**기한이 지났는데 입금이 없는 사람에게 보내는 문구를 만들지 않는다**(소유자 결정).
운영자가 개인적으로 연락한다. 그래서 「자동으로 취소되었습니다」류의 문구가 여기에 없다 —
자동 취소 자체가 없기 때문이다.

## 등록 순서

1. 카카오톡 설정 → **발신 프로필 등록**
2. 카카오톡 설정 → **알림톡 템플릿 등록** ← 위 아홉 개가 여기 들어간다
3. 연동 서비스 신청 페이지 → 담당자 정보 · 약관 동의
4. 승인 후 **API 키 발급** → 환경변수에 넣으면 끝

승인받은 템플릿 코드는 운영자 화면의 「문구 관리」에서 각 문구에 적는다.
심사 상태는 REG(등록) → REQ(심사 요청) → APR(승인) / REJ(반려)다.
